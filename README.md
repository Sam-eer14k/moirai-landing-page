# MoirAI Cloud

Landing page for MoirAI Cloud, makers of Synaptix™, an AI infrastructure
operating platform that runs compute, networking, storage and monitoring from
one console, and Synaptik™ Cell, its lighter compute execution model. The page
is aimed at infrastructure teams in data centers, enterprises, regulated
environments and edge operations, many of them planning a move off VMware.

## What's here

```
index.html          The site. Generated by build.ps1. Open it or serve it.
site.webmanifest    Web app manifest (icons, theme colour).
assets/             Logo, favicons, founder photos, blog covers, hero poster and hero videos.
src/                Sources the site is built from. Edit these, not index.html.
wordpress-theme/    The same site as an installable WordPress theme (PHP).
docs/WIREFRAME.md   The conversion wireframe the layout was planned from.
build.ps1           Rebuilds index.html and regenerates the theme.
.nojekyll           Tells GitHub Pages to serve assets/ verbatim.
```

## View it locally

Open `index.html` in a browser. For the fonts and video to load reliably, serve
it over HTTP rather than the `file://` protocol:

```bash
# Python 3
python -m http.server 8000
# then visit http://localhost:8000
```

## Host it on GitHub Pages

1. Push this folder to a GitHub repository (see below).
2. In the repo, go to **Settings > Pages**.
3. Under **Build and deployment**, set **Source** to *Deploy from a branch*, pick
   the `main` branch and the `/ (root)` folder, and save.
4. The site goes live at `https://<your-username>.github.io/<repo-name>/` within
   a minute or two.

The folder is already a git repository with its work committed on `main`, so
you only need to add the remote and push:

```bash
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

`index.html` is at the repo root and every path in it is relative, so Pages
serves it as the home page with no extra configuration, including from a
`/<repo-name>/` sub-path.

## Editing the site

`index.html` is generated with all CSS and JS inlined, so do not edit it by hand.
Edit the sources instead:

```
src/_head.html      <head> contents: title, meta, favicons, fonts, structured data
src/_body.html      Page markup and all visible copy
src/css/theme.css   All styles (colour tokens at the top, sampled from the logo)
src/js/main.js      All interaction (operating map, explorer, roadmap, calculator,
                    readiness check, FAQ search, forms). Calculator assumptions are
                    in the CALC block at the very top.
```

Then rebuild:

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

That regenerates `index.html`, and also rewrites `wordpress-theme/style.css`,
`wordpress-theme/front-page.php` and `wordpress-theme/assets/js/main.js` from the
same sources and mirrors `assets/` into the theme, so both deliverables stay in
step. `functions.php` and `index.php` are edited in place. The build stops if a
hero-video still is used outside the hero, if an em or en dash slips into the
copy, or if the CSS has an unbalanced quote.

## The WordPress theme

`wordpress-theme/` is a self-contained theme (`style.css`, `front-page.php`,
`functions.php`, `index.php`, `screenshot.png`, `assets/`). GitHub Pages ignores
it because Pages does not run PHP. To use it, copy the folder into a WordPress
install under `wp-content/themes/`, activate it, then set a static front page
under **Settings > Reading**.

In WordPress the contact form posts to `admin-post.php` and emails the message
with `wp_mail`. The destination defaults to the site admin email and can be
changed under **Settings > General > MoirAI enquiry email**. Make sure the host
can send mail (an SMTP plugin is the usual fix if it can't).

## Notes

- The static site has no server, so on GitHub Pages the contact form opens the
  visitor's email app with the message filled in, addressed to
  support@moiraicloud.ai (the only address the client publishes; it is listed
  for technical issues). Change `$LeadEmail` in `build.ps1` if sales has its own
  inbox. The WordPress theme sends messages for real.
- The hero background video is a 1920px re-encode of the 18 MB 4K original:
  `moirai-hero.webm` (0.85 MB) and `moirai-hero.mp4` (2.0 MB), plus a 960px
  `moirai-hero-sm.mp4` (0.6 MB) for phones. All are well within GitHub's limits.
  It pauses off screen, on the pause button, and for reduced-motion visitors.
- Nothing outside the hero uses footage from the video. Section visuals are
  inline SVG, a canvas node network and console mockups drawn in code. The only
  photos are the two founders and the three blog covers, all from moiraicloud.ai.
- Colours are sampled from the logo file: wordmark blue #004AAE and the eye
  ring's #2080C0 to #52D0E2 gradient. Navy #06142F is the wordmark hue darkened.
  All colours are custom properties at the top of `src/css/theme.css`.
- The logo is used exactly as supplied (`moirai-logo.png`), trimmed to its alpha
  box as `logo-h41.png` / `logo-h82.png`. On navy it sits on a small white tile
  rather than being recoloured. The supplied favicon is kept as `moirai-favicon.png`;
  `favicon.ico`, the 16/32 px icons, the Apple touch icon and the 192/512 px icons
  were generated from it.
- Fonts (Bricolage Grotesque, Instrument Sans, JetBrains Mono) load from Google
  Fonts, so the live site needs an internet connection for the intended typography.
- Product names follow the client's site: Synaptix™ (the platform) and
  Synaptik™ Cell (the compute technology).
- Motion respects `prefers-reduced-motion`: the custom cursor, magnetic buttons,
  hero video, map pulses, marquee, console sequence and scroll reveals are off or
  static, and numbers show their final values.
- `og:image` uses a relative path. Some social networks need an absolute URL, so
  set it to the live address once the domain is known.

## Before launch

Every unverified detail is marked `[CONFIRM: ...]` in the page text and shows on
the page as a muted dashed tag (class `.confirm`). Search `src/_body.html` for
`CONFIRM`, replace each with the real answer (or delete the sentence), then run
`build.ps1`. To hide any that remain, add `.confirm { display: none; }` to the CSS.

1. Pricing: Synaptix pricing model (comparison table and FAQ); whether VMware
   licensing is per-core subscription bundles on the vendor's terms.
2. Synaptik™ Cell figures: typical consolidation ratio, density gain, memory
   overhead compared with VMs, workloads per host.
3. Calculator assumptions (`CALC` in `src/js/main.js`): density gain (30% now),
   amortized hardware cost per server per year ($2,500 now), share of licensing
   removed (100% now).
4. Rollout timings: discovery call length, review duration, pilot length,
   migration timeline.
5. Contact: typical reply time, and a sales inbox if not support@.
6. Founders: a two-line bio each for Robert and Daniel Twitchell, and a sharper
   photo of Daniel (the only source is 294 px wide).
7. FAQ: hardware requirements, air-gapped support.

Also worth confirming: the roadmap statuses (read 2026-10-28) and permission to
use the founder photos and blog covers.
